# ADR-012: FFmpeg Drawtext Uses Textfile on Windows

## Status
Accepted

## Context
FFmpeg drawtext inline text parameter fails on Windows when text contains colons — Windows drive letter paths (C:) are parsed as FFmpeg filter separators. Escaping attempts with backslash and single quotes did not resolve reliably.

During Phase S3 development, the attribution text "Gameplay via: CohhCarnage" caused FFmpeg parsing errors:
```
Error parsing filterchain 'drawtext=text='Gameplay via: CohhCarnage':fontcolor=white:...'
```

Multiple escaping approaches were attempted:
- Backslash escaping (`\:`) - failed
- Single quote wrapping - failed  
- Double quote wrapping - failed
- Smart apostrophe substitution - failed

## Decision
All FFmpeg drawtext calls use the textfile parameter. Text is written to a temporary file, path passed to drawtext. Temporary file cleaned up after assembly.

### Implementation Pattern
```python
# Write text to temporary file
textfile = output_video.parent / "attribution_text.txt"
with open(textfile, 'w', encoding='utf-8') as f:
    f.write(attribution)

# Convert to absolute path and escape special characters for FFmpeg
textfile_abs = str(textfile.resolve()).replace("\\", "\\\\").replace(":", "\\:")

# Use textfile parameter in FFmpeg command
subprocess.run([
    get_ffmpeg_path(), "-y", "-i", str(input_video),
    "-vf", f"drawtext=textfile='{textfile_abs}':fontcolor={text_color}:...",
    ...
])

# Clean up textfile
if textfile.exists():
    textfile.unlink()
```

## Consequences
- `core/assembler.py` `_add_attribution_text()` uses textfile always
- `core/assembler.py` `_add_lower_third_text()` uses textfile always  
- `core/assembler.py` `preprocess_segment()` uses textfile always
- `produce_dave_shorts.py` uses textfile always
- Any future FFmpeg text overlay uses textfile
- Inline drawtext text= parameter is never used on Windows
- Temporary files created and cleaned up for each text overlay
- sanitize_drawtext() function retained but no longer actively used
